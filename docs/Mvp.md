# 博览(BiuViewer)MVP 开发任务清单

> 依据: [Prd.md](./Prd.md) 第二章 P0 功能、第三章 P0 分发要求、第五章 MVP 验收标准;技术方案参考 [Arch.md](./Arch.md)。

## 一、MVP 范围

### 1.1 目标

跑通 PRD 定义的验收闭环:

**打开文件夹 → 缩略图/列表浏览 → 适应窗口/缩放/平移 → 上一张/下一张 → EXIF 方向正确 → GIF 可播放 → 内存不随翻页持续增长 → 三平台 CI 产物可下载运行**

### 1.2 纳入 MVP 的功能

| 类别 | 功能 | 来源 |
| :--- | :--- | :--- |
| 文件打开 | 对话框打开图片/文件夹、拖拽打开、命令行打开、文件夹自然排序 | PRD 2.1.1 |
| 图片显示 | 适应窗口、1:1 原始尺寸、缩放(按钮/滚轮/重置)、拖拽平移、光标锚点缩放 | PRD 2.1.2 |
| 图片浏览 | 上一张/下一张(方向键 + 按钮)、旋转/翻转/重置、EXIF 方向校正 | PRD 2.1.3 |
| 显示模式 | 进入/退出全屏 | PRD 2.1.4 |
| 异常处理 | 加载状态、损坏/不支持/权限不足提示,全程不崩溃 | PRD 2.1.5 |
| 格式 | PNG / JPEG / BMP / GIF / WebP / TIFF / ICO 静态解码 | PRD 2.2.1 |
| 性能 | GPU 纹理渲染、后台解码、按字节预算的 LRU 缓存 | PRD 2.5.1-2.5.3 |
| 分发 | macOS 未签名 .app、Windows 便携 zip、Linux tar.gz + install.sh | PRD 3.1-3.3 |
| 工程 | GitHub Actions 矩阵构建、tag 自动发布 + SHA256 校验和 | PRD 3.4-3.5 |

### 1.3 为满足验收标准而提前的 P1 能力(最小实现)

PRD 第五章的验收链路包含两项在第二章标为 P1 的功能,MVP 只做最小可用版本:

| 功能 | MVP 做到 | 留给 P1 |
| :--- | :--- | :--- |
| 缩略图条 | 底部单行缩略图条,点击跳转,高亮当前项;缩略图仅内存缓存 | 网格视图、尺寸调节、磁盘缩略图缓存 |
| GIF 动画 | 按帧延迟播放 GIF,切图时停止 | 暂停/继续、帧计数显示、APNG、动画 WebP |

### 1.4 明确不在 MVP 内

完整快捷键体系与自定义、右键菜单、剪贴板、主题切换、相邻预加载、降采样/瓦片、磁盘缓存、解码任务主动取消、AVIF/HEIC/SVG、配置持久化、日志轮转、安装程序/.deb/AppImage、国际化。

## 三、开发任务

> 约定: 每个任务给出交付物与验收标准,验收标准全部勾选才算完成。估时单位为人天,仅供排期参考。

### M0 工程基础

#### T01 初始化 Cargo 工作区

- **依赖**: 无 **估时**: 0.5
- **交付物**: 按 Arch 7.1 / 7.2 建立工作区,包含 `biuviewer`、`biuviewer-core`、`biuviewer-ui`、`biuviewer-decoder`、`biuviewer-platform` 五个 crate;release profile 配置 LTO 与 strip;`rustfmt.toml`、`.gitignore`
- **验收标准**:
  - [ ] `cargo build --workspace` 与 `cargo test --workspace` 在本地通过
  - [ ] 二进制名为 `biuviewer`,`--version` 输出与 `Cargo.toml` 版本一致
  - [ ] crate 依赖方向符合 Arch 2.2.2,无循环依赖

#### T02 集成 GPUI 并打开空窗口

- **依赖**: T01 **估时**: 1
- **交付物**: 主程序启动 GPUI 应用,打开标题为 "BiuViewer" 的窗口,显示空状态页("打开图片或拖入文件夹")
- **验收标准**:
  - [ ] macOS / Windows / Linux(X11 与 Wayland 各一)均可启动并正常关闭
  - [ ] 窗口可缩放、最小化,关闭后进程退出
  - [ ] 冷启动到窗口可见 < 1s(release 构建)

#### T03 日常 CI 工作流

- **依赖**: T01 **估时**: 1
- **交付物**: `.github/workflows/ci.yml`,在 PR 与 main 推送时于 macOS / Windows / Ubuntu 三个 runner 执行 `fmt --check`、`clippy -D warnings`、`test`
- **验收标准**:
  - [ ] 三平台任务全部通过,Linux 依赖按 Arch 7.3 安装
  - [ ] 启用 `Swatinem/rust-cache`,二次构建耗时明显下降
  - [ ] 故意引入 clippy 警告时 CI 失败

#### T04 统一错误类型与基础日志

- **依赖**: T01 **估时**: 0.5
- **交付物**: `biuviewer-core` 中定义 `ViewerError`(`NotFound` / `PermissionDenied` / `Unsupported` / `Corrupted` / `Io`),基于 `thiserror`;接入 `tracing` 输出到 stderr,级别由 `RUST_LOG` 控制
- **验收标准**:
  - [ ] 每种错误都有面向用户的中文描述文本
  - [ ] `std::io::Error` 能正确映射到 `NotFound` / `PermissionDenied`
  - [ ] 业务代码中不出现 `unwrap()` / `expect()`(测试代码除外),由 clippy 规则约束

### M1 解码与文件

#### T05 格式识别

- **依赖**: T04 **估时**: 0.5
- **交付物**: `FormatDetector`,优先按文件头魔数识别,扩展名作为兜底;提供 `supported_extensions()` 供文件夹扫描与错误提示复用
- **验收标准**:
  - [ ] 正确识别 PNG / JPEG / BMP / GIF / WebP / TIFF / ICO
  - [ ] 扩展名错误(如 PNG 改名为 .jpg)仍按真实格式识别
  - [ ] 非图片文件返回 `Unsupported`

#### T06 静态图片解码

- **依赖**: T05 **估时**: 1
- **交付物**: `DecoderBackend` trait 与基于 `image` crate 的默认实现,输出 RGBA8 像素缓冲 + 宽高;解码函数为同步纯函数,便于放入后台线程
- **验收标准**:
  - [ ] 7 种 P0 格式各有测试样本并解码成功
  - [ ] 截断/损坏文件返回 `Corrupted`,不 panic
  - [ ] 对超出上限的尺寸(如单边 > 32768 或像素数 > 2 亿)返回明确错误,避免内存爆炸
  - [ ] 10MB JPEG 解码 < 1s(release,CI runner 基线)

#### T07 EXIF 方向校正

- **依赖**: T06 **估时**: 1
- **交付物**: 读取 EXIF Orientation(1-8)并在解码后应用到像素,参考 Arch 4.2;无 EXIF 或读取失败时按 1 处理
- **验收标准**:
  - [ ] 8 个方向值各有测试样本,输出像素与预期一致
  - [ ] 用户旋转/翻转叠加在校正后的图像上,"重置"不会撤销 EXIF 校正
  - [ ] EXIF 数据损坏不影响图片正常显示

#### T08 文件夹扫描与自然排序

- **依赖**: T05 **估时**: 1
- **交付物**: `FolderScanner`,非递归扫描目录,按扩展名过滤受支持格式,按文件名自然排序(`img2` 排在 `img10` 前),忽略隐藏文件
- **验收标准**:
  - [ ] 自然排序单测覆盖数字、大小写、中文文件名
  - [ ] 1000 个文件的目录扫描 < 100ms(不含解码)
  - [ ] 无权限目录返回 `PermissionDenied`,空目录返回空列表并由 UI 显示空状态

#### T09 图片列表模型

- **依赖**: T08 **估时**: 0.5
- **交付物**: `ImageList`,持有排序后的路径列表与当前索引;提供 `next` / `prev` / `jump(index)`;从单张图片打开时扫描其所在目录并定位到该文件
- **验收标准**:
  - [ ] 首张按"上一张"、末张按"下一张"不越界(MVP 行为: 停在边界)
  - [ ] 打开单张图片后可在同目录内翻页,当前索引指向该文件
  - [ ] 单测覆盖空列表、单元素、边界跳转

### M2 显示与变换

#### T10 图像纹理渲染

- **依赖**: T02、T06 **估时**: 2
- **交付物**: `ImageViewer` 视图,将 RGBA 缓冲上传为 GPUI 图像资源并通过 GPU 绘制,参考 Arch 3.3.1
- **验收标准**:
  - [ ] 静态图片可正确显示,颜色与系统预览一致(无 RGB/BGR 颠倒、无预乘错误)
  - [ ] 切换图片后旧纹理被释放(通过内存观测确认)
  - [ ] 渲染路径不做 CPU 逐像素绘制

#### T11 视口与适应窗口

- **依赖**: T10 **估时**: 1
- **交付物**: `ViewportManager`,实现 Fit-to-window(小图不放大)与 1:1 原始尺寸两种模式;窗口尺寸变化时在 Fit 模式下自动重算
- **验收标准**:
  - [ ] Fit 模式下图片完整可见且居中,长宽比不变
  - [ ] 1:1 模式下一个图像像素对应一个物理像素(考虑 HiDPI 缩放因子)
  - [ ] 拖拽调整窗口时无明显闪烁或跳动
  - [ ] 视口计算逻辑有纯函数单测

#### T12 缩放

- **依赖**: T11 **估时**: 1.5
- **交付物**: 工具栏放大/缩小/重置按钮、鼠标滚轮/触控板缩放、键盘 `+` / `-` / `0`;缩放范围 1%-3200%,以光标位置为锚点
- **验收标准**:
  - [ ] 滚轮缩放时光标下的图像像素保持在光标下(误差 ≤ 1px)
  - [ ] 按钮与键盘缩放以视口中心为锚点
  - [ ] 重置回到 Fit 模式
  - [ ] 连续缩放保持 60fps(4K 图片)

#### T13 平移

- **依赖**: T12 **估时**: 1
- **交付物**: 图片大于视口时支持鼠标拖拽平移;平移边界约束,图片小于视口的方向保持居中
- **验收标准**:
  - [ ] 不能把图片完全拖出视口
  - [ ] 拖拽过程 60fps,无跳帧
  - [ ] 图片不大于视口时拖拽无效果,光标不显示抓手

#### T14 旋转与翻转

- **依赖**: T11 **估时**: 1
- **交付物**: `TransformState`,支持顺/逆时针 90° 旋转、水平/垂直翻转、重置;通过渲染变换实现,不重新解码,参考 Arch 3.3.3
- **验收标准**:
  - [ ] 旋转 90°/270° 后 Fit 模式按交换后的宽高计算
  - [ ] 旋转 4 次或同向翻转 2 次回到原状态
  - [ ] 切换到下一张图片时变换自动重置
  - [ ] 变换组合逻辑有单测

#### T15 全屏模式

- **依赖**: T11 **估时**: 1
- **交付物**: `F11` / `F` 切换全屏,`Esc` 退出全屏;全屏时隐藏工具栏,鼠标移到底部时浮现
- **验收标准**:
  - [ ] 三平台进入/退出全屏正常,退出后恢复原窗口尺寸
  - [ ] 全屏下缩放、平移、翻页、旋转均可用
  - [ ] 进出全屏时 Fit 模式自动重算

#### T16 工具栏与状态栏

- **依赖**: T12、T14 **估时**: 1
- **交付物**: 工具栏(打开、上一张/下一张、放大/缩小/重置、1:1、旋转、翻转、全屏);状态栏显示文件名、序号 `n / total`、分辨率、缩放比例
- **验收标准**:
  - [ ] 每个按钮都有 tooltip 且功能可用
  - [ ] 状态栏信息随翻页、缩放实时更新
  - [ ] 未打开图片时与图片无关的按钮置灰

### M3 浏览与加载

#### T17 文件对话框打开

- **依赖**: T09、T10 **估时**: 1
- **交付物**: `Ctrl/Cmd+O` 打开图片、`Ctrl/Cmd+Shift+O` 打开文件夹,使用系统原生对话框;图片对话框按支持格式过滤
- **验收标准**:
  - [ ] 三平台均弹出原生对话框
  - [ ] 打开文件夹后显示第一张图片,打开单张图片后可同目录翻页
  - [ ] 取消对话框不改变当前状态

#### T18 拖拽打开

- **依赖**: T17 **估时**: 0.5
- **交付物**: 支持拖入图片文件或文件夹,拖入时显示高亮遮罩;拖入多个文件时取第一个
- **验收标准**:
  - [ ] 拖入图片、文件夹均按 T17 的规则打开
  - [ ] 拖入不支持的文件显示"不支持的格式"提示,当前图片不受影响

#### T19 命令行打开

- **依赖**: T17 **估时**: 0.5
- **交付物**: 解析 `biuviewer <path>`,路径可为图片或目录,支持相对路径;提供 `--help` / `--version`
- **验收标准**:
  - [ ] `biuviewer image.png`、`biuviewer ./photos/` 均正确打开
  - [ ] 路径不存在时窗口正常打开并显示错误提示,进程不退出
  - [ ] macOS 通过"打开方式"传入的文件同样生效(处理 GPUI 的 open-urls 事件)

#### T20 键盘与按钮翻页

- **依赖**: T09、T16 **估时**: 0.5
- **交付物**: `←` / `→` 及工具栏按钮翻页;`Home` / `End` 跳到首张/末张
- **验收标准**:
  - [ ] 按住方向键连续翻页时 UI 不卡死,最终停在正确的图片上
  - [ ] 翻页响应(从按键到显示新图片或加载状态) < 100ms

#### T21 后台异步解码

- **依赖**: T06、T10 **估时**: 2
- **交付物**: 解码在后台线程池执行,UI 线程只负责提交任务和接收结果;每次请求附带递增的请求序号,过期结果直接丢弃,参考 Arch 4.1.1
- **验收标准**:
  - [ ] 解码大图期间窗口可拖动、按钮可点击
  - [ ] 快速连续翻页 20 次,最终显示的是最后一次请求的图片,不出现"闪回"
  - [ ] 解码线程 panic 时被捕获并转为错误提示,主程序不崩溃

#### T22 内存 LRU 缓存

- **依赖**: T21 **估时**: 1.5
- **交付物**: `MemoryCache`,以 `width × height × 4` 计算占用,按字节预算(默认 512MB)淘汰最久未使用项,参考 Arch 3.2.2;重复访问命中缓存不再解码
- **验收标准**:
  - [ ] 缓存总占用始终 ≤ 预算,单测验证淘汰顺序
  - [ ] 单张超过预算的图片仍可显示,但不进入缓存
  - [ ] 在 500 张 12MP 照片中连续翻页,进程常驻内存稳定在预算 + 基线范围内,不持续增长

#### T23 加载状态与错误提示

- **依赖**: T21、T04 **估时**: 1
- **交付物**: 解码超过 150ms 时显示加载指示器;解码失败时在视口中央显示错误卡片(图标 + 原因 + 文件名),"不支持格式"时列出支持的格式
- **验收标准**:
  - [ ] 损坏文件、不支持格式、无权限文件分别显示对应提示
  - [ ] 出错后仍可翻页到下一张
  - [ ] 用包含上述异常文件的测试目录执行完整翻页,应用不崩溃

#### T24 缩略图条(最小实现)

- **依赖**: T21、T22 **估时**: 2
- **交付物**: 窗口底部单行缩略图条,可横向滚动;仅为可见区域生成缩略图(长边 128px,后台生成,单独的内存 LRU);点击跳转,当前项高亮并自动滚动到可见位置;可通过工具栏按钮隐藏
- **验收标准**:
  - [ ] 1000 张图片的文件夹:打开到首张可见 < 3s,缩略图条滚动流畅
  - [ ] 缩略图生成不阻塞主图加载(主图请求优先)
  - [ ] 缩略图应用 EXIF 方向
  - [ ] 解码失败的项显示占位图标

### M4 动画

#### T25 GIF 动画播放(最小实现)

- **依赖**: T21 **估时**: 2
- **交付物**: 识别多帧 GIF,解码所有帧及帧延迟,按原生帧率循环播放(延迟 < 20ms 时按 100ms 处理,与主流浏览器一致);切换图片时停止计时器并释放帧数据
- **验收标准**:
  - [ ] 测试样本播放速度与浏览器一致
  - [ ] 播放期间缩放、平移、旋转正常
  - [ ] 单帧 GIF 按静态图处理
  - [ ] 帧数据计入内存缓存预算;来回切换 GIF 若干次后内存回落

### M5 打包发布

#### T26 macOS 打包

- **依赖**: T19 **估时**: 1
- **交付物**: `scripts/bundle-macos.sh`,按 Arch 7.4.1 生成通用二进制 `.app` 与 `BiuViewer-v{version}-macOS-universal.zip`;Info.plist 声明图片类型以支持"打开方式"
- **验收标准**:
  - [ ] Intel 与 Apple Silicon 机器均可运行(`lipo -info` 显示两种架构)
  - [ ] 按 README 执行 `xattr -cr` 或右键打开后可正常启动
  - [ ] 在 Finder 中对图片使用"打开方式 → BiuViewer"能直接打开

#### T27 Windows 打包

- **依赖**: T19 **估时**: 0.5
- **交付物**: `scripts/bundle-windows.sh`,生成 `BiuViewer-v{version}-windows-x64.zip`,包含 exe 与 README.txt;exe 嵌入图标与版本信息,release 构建不弹出控制台窗口
- **验收标准**:
  - [ ] 在未安装 Rust/VC 开发环境的干净 Windows 10 与 11 上解压即可运行(静态链接 CRT 或确认系统自带运行库)
  - [ ] 双击运行不出现黑色控制台窗口
  - [ ] 将图片拖到 exe 图标上可打开

#### T28 Linux 打包

- **依赖**: T19 **估时**: 0.5
- **交付物**: `scripts/bundle-linux.sh`,生成 `BiuViewer-v{version}-linux-x86_64.tar.gz`,包含二进制、`.desktop`、图标、`install.sh`、README
- **验收标准**:

### 5.2 主要风险

| 风险 | 影响任务 | 应对 |
| :--- | :--- | :--- |
| GPUI 在 Windows / Linux 上 API 不稳定或存在缺陷 | T02、T10、T15 | M0 阶段先做三平台空窗口 + 纹理显示的技术验证;固定 GPUI 版本(git rev) |

| Linux 发行版图形栈差异(Wayland/X11、Vulkan 驱动) | T02、T28 | CI 之外至少在两个发行版实机验证;README 列出依赖要求 |
