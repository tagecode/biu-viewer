# 性能基准

记录 BiuViewer 在 MVP 阶段（T30）的性能数据、测试方法与结论。

## 测试机

| 项目 | 配置 |
| :--- | :--- |
| CPU | Intel Core i7-9750H @ 2.60GHz（6 核 12 线程） |
| 内存 | 16 GB |
| 系统 | macOS 26.5.1（Darwin 25.5.0），x86_64 |
| 显示 | Retina，2× 缩放 |
| 工具链 | Rust 1.99.1 |
| 构建 | `--release`：`opt-level = 3`、`lto = true`、`codegen-units = 1`、`strip = true` |

> 表中数据来自本机一次测量，用于判断是否达到 PRD 5.2 的目标，不代表所有机器。Windows / Linux 的数据需在对应平台按同样步骤复测。

## 验收指标对照

| 指标（PRD 5.2） | 目标 | 实测 | 结论 |
| :--- | :--- | :--- | :--- |
| 1000 张图片文件夹加载 | < 3 s | 扫描 + 排序 13.4 ms；启动到首图可见约 1.2 s（含窗口创建） | 通过 |
| 单张 10MB 图片加载 | < 1 s | 10.6 MB PNG（2000×1500）解码 18.9 ms | 通过 |
| 翻页响应 | < 100 ms | 缓存命中 0.0002 ms；未命中 400×300 PNG 3.0 ms，12MP PNG 124.6 ms | 通过（12MP 首次解码受解码速度限制） |
| 空闲内存基线 | < 200 MB | 打开 1000 张目录后空闲约 50–61 MB | 通过 |
| 缩放平移 | ≥ 60 fps | 单张纹理一次四边形绘制，未逐帧采样 | 待人工确认 |
| 连续翻页内存 | 不持续增长 | 500 张 426 MB → 1000 张 782 MB → 回退到已缓存区间 378 MB | 通过（受 512 MB 缓存预算约束） |

## Criterion 微基准

```bash
cargo bench --workspace
```

测试素材在内存中合成，不含磁盘 I/O，用于观察回归而非绝对值。

| 基准 | 时间 | 吞吐 |
| :--- | ---: | ---: |
| `cache-hit-2mb`（512 MB 预算内命中 2 MB 条目） | 178.7 ns | — |
| `cache-insert-evict`（64 MB 预算下插入触发淘汰） | 572.7 ns | — |
| `decode/png-4k`（3840×2160） | 87.0 ms | 183.7 MiB/s |
| `decode/jpeg-4k`（3840×2160） | 67.0 ms | 22.7 MiB/s |
| `decode/png-12mp`（4000×3000） | 124.6 ms | 185.6 MiB/s |
| `scan-1000`（扫描 1000 个文件） | 13.4 ms | — |
| `natural-sort-1000`（1000 个文件名自然排序） | 1.17 ms | — |

JPEG 吞吐低于 PNG 是合成素材的特性：随机噪声经 JPEG 编码后体积小，解码耗时主要由 IDCT 与色彩转换决定，与文件体积不成正比。

## 单图解码（真实文件）

```bash
cargo run --release -p biuviewer-decoder --example decode_file -- /tmp/biu-bench/large-10mb.png
```

| 文件 | 尺寸 | 帧数 | 体积 | 解码耗时 |
| :--- | :--- | ---: | ---: | ---: |

## 内存

采样命令（macOS 用 `ps -o rss=`，Linux 用 `ps -o rss=`，Windows 用任务管理器）：

```bash
./scripts/bench-manual.sh /tmp/biu-bench
```

| 场景 | 常驻内存 |
| :--- | ---: |
| 刚启动，未打开任何图片 | 59.5 MB |
| 打开 1000 张目录，空闲 15 s | 约 50–61 MB（多次采样，15 s 内变化 < 1 MB） |
| 连续翻页 50 张 | 103 MB |
| 连续翻页 200 张 | 211 MB |
| 连续翻页 500 张 | 426 MB |
| 连续翻页 1000 张 | 782 MB |
| 从第 1000 张回翻到第 500 张 | 378 MB（回落到缓存预算内） |

结论：内存由 512 MB 主图缓存 + 64 MB 缩略图缓存按字节淘汰约束，翻页越多越接近预算上限，但不会无限增长；回访已缓存图片时内存回落。1000 张小图（400×300）可以全部留在预算内，因此数值一路上升到接近预算；用 12MP 照片测试时，缓存可容纳的更少，常驻内存更早趋于平稳。

> 若需要更激进的省内存表现，可下调 `crates/biuviewer-ui/src/viewer_app.rs` 中的 `CACHE_BUDGET`，代价是回翻时需要重新解码。

## 手动测试步骤

1. 生成素材（1000 张图片、10MB 图片、4K 图片、40 帧 GIF、损坏文件、非图片文件，以及 `formats/` 7 种格式样张与 `exif/` 8 种方向样张）：

   ```bash
   cargo run --release -p biuviewer-decoder --example make_assets -- /tmp/biu-bench
   ```

2. 启动应用并打开 1000 张目录，观察首图出现时间与缩略图按需加载：

   ```bash
   ./target/release/biuviewer /tmp/biu-bench/1000-photos
   ```

3. 按住 `→` 连续翻页，在「活动监视器」中观察内存。内存应升到缓存预算附近后不再单调增长；回翻时回落。

4. 打开 10MB / 4K 图片，感受解码延迟；打开 GIF 确认按帧率循环播放。

5. 缩放与平移：滚轮缩放、拖拽平移，观察是否卡顿（GPU 侧只绘制一个纹理四边形，帧率取决于合成器）。

### 生成更接近真实场景的素材

内置素材是合成图。如果想用真实照片复测缓存表现，把 500 张 12MP 照片（JPEG，单张 3–6 MB）放进同一目录，再用第 3 步的方法观察内存：

```bash
./target/release/biuviewer ~/Pictures/12mp-sample
```

## 已知差异

- `decode/jpeg-4k` 的吞吐低于 PNG 属于合成素材特性，见上文说明。
- 帧率（≥ 60 fps）无法用脚本稳定测量，需在三平台发布产物上人工确认。
